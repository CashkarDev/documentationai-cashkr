## Purpose

Lets a partner request deletion of their vendor account from the app; ops calls them, refunds unused credits (₹10 per credit), and an admin approves (which anonymises the vendor and their cashboys, purges photos/documents, revokes sessions and sends an SMS) or rejects within a 7-working-day SLA.

## Core Business Logic

1.  **Request**: countActiveVendorOrders = MasterLeads with primaryStatus ∈ \{InProgress, PickupDelayed, Reserved\} AND secondaryStatus ∈ \{Assigned, InspectionStarted, OutForPickup, Reserved\} + unexpired ReservedLeads in PENDING/RESERVED. If &gt; 0 the vendor is told to finish first. If creditsAvailable &gt; 0, a payout destination is required (payoutUpiId or payoutQrUrl or account number + IFSC). Reference id generation retries up to 5 times on collision; a P2002 from the pending-per-vendor index returns the racing row.

2.  **Cancel**: only PENDING; conditional update protects against a concurrent approval.

3.  **Approve** (approveDeletionRequest): checks above, then collects asset URLs (8 Vendors document columns, payout QR, each cashboy's Aadhaar/selfie, PartnerLoginSession.selfieImageUrl, attendance punch-in/out selfies). In one transaction: insert TokenBlacklist markers for vendor and cashboys (10-year expiry); delete ChatAuditLog + ChatRoom for the vendor; delete PartnerLoginSession rows; null attendance selfie URLs; delete VendorNotification, VendorNotificationEvent, VendorPincodes; anonymise Vendors (Deleted Vendor, deleted+&lt;id&gt;@deleted.cashkr.local, phone DELETED\_&lt;id&gt;\_&lt;stamp&gt;, all images null, deviceAssigned=\[\], credits 0, maxLeads 0, isApproved=false, status="barred", isDeleted=true, deletedAt); anonymise each cashboy; mark request COMPLETED (payoutQrUrl nulled). After commit, best effort: delete objects from the bucket in batches of 20 (deleteFromS3Bucket), then sendAccountDeletionSMS (SmsUtility). The Vendors row is kept because invoices, payments and leads reference it.

4.  **Reject**: conditional update to REJECTED with adminNote (shown to the vendor in the app).

5.  **SLA**: deletionDueBy = requestedOn + 7 working days (IST Sat/Sun skipped, no holiday calendar); isOverdue only for PENDING.

## Status / State Machine

PENDING → CANCELLED (vendor) \| REJECTED (admin) \| COMPLETED (admin approve). Terminal states cannot change. One PENDING per vendor (partial unique index).

## Validations & Rules

zod createDeletionRequestSchema: reason 1–255, details ≤200, valid UPI id, account number 9–18 digits, valid IFSC (uppercased), bank name/holder ≤120; bank trio all-or-none. approveDeletionSchema, rejectDeletionSchema (adminNote ≤500). Token/body vendorId mismatch → 403. CREDIT_TO_RUPEE = 10 is used in the vendor-facing message.
