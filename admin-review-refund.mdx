## Overview

**Sidebar:** Vendors → Money → **Review Refunds** (`/review-refunds`)

Vendors upload proof of a customer review for a completed order. On this screen you verify each proof and decide whether the vendor gets a credit refund. The refund is a **percentage of the order credits** — the current rate is shown in the page subtitle (for example, "Current refund: 5% of order credits") and is configured on [Review Refund Settings](/admin-panel/vendors/review-refund-settings) via the **Refund Settings** button (top right).

## What the screen shows

### Status tabs

| Tab | Shows |
| --- | --- |
| **Pending** (default) | Newly uploaded proofs waiting for a decision. |
| **Accepted** | Proofs that were accepted and refunded. |
| **Rejected** | Proofs that were rejected (no refund). |
| **Revoked** | Previously accepted refunds that were revoked. |
| **All** | Every submission. |

### Table columns

| Column | Description |
| --- | --- |
| Proof | Thumbnail of the uploaded review screenshot/photo. Click it to open the **Review Proof** dialog. |
| Order | Order token and device (category · model). |
| Vendor | Vendor name and phone. Removed accounts show as "Deleted Vendor". |
| Order Credits | Credits charged to the vendor for the order. |
| Refund | Credits to be refunded (Accepted rows also show the % used, e.g. "4 (5%)"). |
| Status | Pending, Accepted, Rejected or Revoked badge. |
| Uploaded | Date the vendor uploaded the proof. |
| Action | Depends on status (see below). |

The refund is calculated as **order credits × refund %** and rounded to whole credits (for example, at 5%: 80 credits → 4, 30 credits → 2).

## Filters & search

- **Status tabs** — Pending / Accepted / Rejected / Revoked / All.
- **Search** — by order token, vendor name or phone ("Search order token / vendor / phone").

## Actions

| Status | Action | Result |
| --- | --- | --- |
| Pending | **Accept** | Marks the proof Accepted and credits the refund to the vendor's wallet. |
| Pending | **Reject** | Marks the proof Rejected; no credits are given. A reason is recorded and shown in the Review Proof dialog. |
| Accepted | **Revoke** | Reverses an accepted refund and moves the item to Revoked. |
| Rejected / Revoked | — | No further action. |

### Review Proof dialog

Clicking a proof thumbnail opens **Review Proof — &lt;order token&gt;**, showing the vendor and device, the full-size proof image, **Order credits**, **Refund** (with %), and — for rejected items — the **Reason**.

## Verification flow

<Steps>
<Step title="Open the Pending tab" icon="list" title-type="p">
Go to **Vendors → Review Refunds**. The Pending tab lists proofs waiting for review, newest first.
</Step>
<Step title="Open the proof" icon="image" title-type="p">
Click the thumbnail to view the full image alongside the order credits and refund amount.
</Step>
<Step title="Verify the review" icon="search" title-type="p">
Confirm the review is genuine, readable and tied to the actual customer and order. If it is unclear, unrelated or does not meet the criteria, do not accept it.
</Step>
<Step title="Accept or Reject" icon="check" title-type="p">
Click **Accept** to refund the credits, or **Reject** (with a reason) to decline. Use **Revoke** on the Accepted tab if an accepted refund later turns out to be invalid.
</Step>
</Steps>

<Callout kind="info">
If the feature is turned off in Review Refund Settings, accepting a review records no refund.
</Callout>

<Callout kind="alert">
A submission can only be refunded once. Once it is accepted or rejected, the Pending actions disappear, which prevents double credit even if two admins open the same item.
</Callout>

## Common issues

| Issue | Cause | Resolution |
| --- | --- | --- |
| Proof image not loading | Network or storage issue | Refresh the page. If it still does not load, escalate to tech support. |
| Credit not applied after accept | Credit write may have failed | Check the vendor's history on **Vendor Fines** (Fines History). If the entry is missing, escalate. |
| Vendor disputes a rejection | Vendor believes the review was valid | Re-check the proof. If the rejection was wrong, consult your lead on remediation. |
| Refund given by mistake | Proof later found invalid | Use **Revoke** on the Accepted tab. |
