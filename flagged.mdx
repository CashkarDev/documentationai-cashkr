## Overview

<Callout kind="info">
  Use the Flagged page in Orders - B2C to track escalated orders that need admin attention due to customer issues, vendor problems, or operational concerns. Any order under Orders - B2C can be flagged from its order detail panel regardless of its current status or section.
</Callout>

The Flagged page lists all orders that the admin team has escalated so you can monitor open issues, resolve them, or reassign the order to a different vendor.

## Summary cards

Use the three summary cards at the top of the page to see the current flagged order situation at a glance:

- **Total Pending** — Total number of flagged orders currently awaiting resolution.
- **Critical (more than 15 minutes)** — Number of flagged orders that have been open for more than 15 minutes without any response or action. These require immediate attention.
- **Avg Response Time** — Average time taken by the admin team to respond to and resolve flagged orders.

When there are no pending flagged orders, the page displays an All Clear message confirming no customer issues are pending at the moment.

<Callout kind="alert">
  The Critical counter tracks orders that have been flagged for more than 15 minutes without any admin response. Treat any non-zero Critical count as an operational emergency and act immediately.
</Callout>

## What the table shows

Each row in the Flagged Orders list represents one escalated order with the following columns:

- **Order** — Order ID and city of the flagged order.
- **Device** — Device model and customer phone number, with a quick call option.
- **Issue** — Problem type selected when the order was flagged (for example, customer not called).
- **Current Vendor** — Name and phone number of the vendor currently assigned to the order.
- **Flagged Vendor** — Vendor who was flagged in relation to the issue.
- **Actions** — Buttons to either resolve the issue or reassign the order to a different vendor.

## Problem types

When flagging an order, the admin must select one of the following problem types:

- **Pickup Not Complete** — The vendor was assigned and confirmed but did not complete the pickup.
- **Customer Not Called** — The vendor did not call the customer before or during the pickup attempt.
- **Vendor Did Not Arrive** — The vendor confirmed the pickup but did not show up at the customer's location.
- **Wrong Price Quoted** — The vendor quoted a different price to the customer than what was agreed.
- **Customer Complaint** — The customer raised a complaint about the vendor's behaviour or service.
- **Document Issue** — There is a problem with the documents provided during the order.
- **Payment Issue** — There is an issue with the payment made or offered to the customer.
- **Other** — Any other issue that does not fit the categories above.

After selecting the problem type, the admin can add a description to provide additional context before submitting the flag.

## How to flag an order

Admins can flag an order from any section under Orders - B2C including All Orders, In Progress, Not Assigned, No Action, Delayed, and Reserved.

<Steps>
  <Step title="Open the order detail" icon="folder">
    Open the order detail page for the relevant order from any Orders - B2C section.
  </Step>

  <Step title="Choose Flag Order" icon="alert-triangle">
    Click the Flag Order option within the order detail panel to start the escalation.
  </Step>

  <Step title="Fill in flag details" icon="edit">
    In the Flag Order popup, select the required Problem Type from the dropdown and optionally add a Description to explain the issue.
  </Step>

  <Step title="Submit the flag" icon="check-circle">
    Click Flag Order to confirm. The order immediately appears in the Flagged page with a pending status.
  </Step>
</Steps>

## Flagged order flow

Use this flow to understand what happens from issue identification to resolution or reassignment.

<Steps>
  <Step title="Identify the issue and flag the order" icon="info">
    An issue is identified on an active order. The admin opens the order detail from any Orders - B2C section, selects Flag Order, and chooses the relevant problem type. The order appears in the Flagged page with a pending status.
  </Step>

  <Step title="Investigate with vendor and customer" icon="users">
    The admin contacts the vendor and, when needed, the customer to investigate what went wrong and gather context about the flagged issue.
  </Step>

  <Step title="Resolve or reassign the order" icon="settings">
    After investigating, the admin either clicks Resolve if the issue is fixed, or clicks Reassign if a new vendor is needed. The order then moves back to the regular order flow with the updated vendor assignment, and the flag is closed and logged.
  </Step>
</Steps>

## Resolving a flagged order

Once the issue has been addressed, resolve the flag directly from the Flagged Orders page:

- Click **Resolve** on the flagged order row to mark the issue as resolved.
- The order is removed from the Flagged list and the flag is closed.
- The resolution is logged against the order for audit and future review.

## Reassigning a flagged order

If the issue is related to the assigned vendor and you need to move the order to a different vendor:

- Click **Reassign** on the flagged order row to open the reassignment flow.
- Select a new vendor for the order.
- The order is reassigned to the new vendor, removed from the current vendor's queue, and the flag remains on record until it is resolved.

## Admin responsibilities

Admins using the Flagged page are responsible for:

- Checking the Flagged page at the start of every shift and throughout the day.
- Responding to all flagged orders within 15 minutes to avoid them appearing in the Critical count.
- Contacting the customer immediately for issues involving vendor no-shows, wrong pricing, or complaints.
- Contacting the flagged vendor to understand their side of the issue before taking action.
- Using Reassign for vendor-related failures and Resolve only after confirming the issue has been addressed.
- Keeping the Average Response Time as low as possible, as it is a key customer service metric.
- Using problem type data over time to identify vendors with recurring issues and addressing them through quality reviews.

## Important notes

<Callout kind="alert">
  Flagging an order does not cancel it and does not remove it from the vendor's queue. The order remains active until you either resolve it in place or reassign it to a new vendor.
</Callout>

<Callout kind="alert">
  All flags are permanently logged against the order and cannot be deleted. This creates a clear audit trail for every escalated issue.
</Callout>

Flagged orders connect with other modules:

- **All Orders** — Orders can be flagged from the All Orders view.
- **In Progress** — Active orders with field issues are commonly flagged from In Progress.
- **Delayed** — Overdue orders with additional complications can be escalated by flagging.
- **Vendors - B2C** — Flagged vendor information links to the vendor's profile for review and trust score impact.
- **Quality - B2C** — Flagged orders and their problem types feed into vendor quality assessments and grading.
- **Not Assigned / No Action** — Unresponsive order situations can be escalated to Flagged when vendor contact fails.
