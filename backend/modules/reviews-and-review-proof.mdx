## Purpose

(a) In-app star/text reviews between the three parties of a completed or failed order (customer ↔ vendor ↔ cashboy). (b) Public display of imported platform reviews (Google/App Store/Play Store). (c) Review-proof refund: after a completed order, the vendor (or the cashboy who worked it) uploads a screenshot proving the customer left a review; once admin accepts it, a configurable % of the order's creditPoints is refunded to the VENDOR's credit wallet.

## Core Business Logic

- **Reviews**: eligibility = order Completed or Failed; each party may review once per lead (checked via existing rows and the composite unique). Submitting stores the other parties' ids on the row so "reviews about X" queries work. getVendorAverageRating (used elsewhere) averages reviewedBy=Customer rows with a rating.

- **Review-proof refund flow**: 1) Vendor or cashboy uploads a screenshot for a Completed order they are stamped on (lead.vendorId / lead.cashboyId). The proof row is always stored under the order's VENDOR (cashboys have no wallet). 2) Row created Pending, attemptCount=1. 3) Admin verifies (accept / reject with rejectReason / revoke) and on accept records refundCredits and refundPercentage and writes a VendorCreditLogs entry with category=ReviewRefund (status Credited); a later revoke debits it back. **The admin accept/reject/revoke and the config editor are NOT in this backend** — the admin panel (ck-admin) does it directly on the shared DB; how the credit is computed there is Unclear from this code beyond the migration comment "refunds a configurable % of the order's creditPoints to the vendor's wallet". 4) Vendor sees Accepted totals in /my and ledger lines in /transactions.

- **Platform reviews**: read-only here; nothing in src or scripts creates PlatformReview or ReviewWidget rows (imported elsewhere — Unclear from code).

## Status / State Machine

ReviewProofStatus: Pending → Accepted \| Rejected (admin, outside this repo); Rejected → Pending on re-upload (vendor/cashboy, resets rejectReason, reviewedByAdminId, reviewedAt, increments attemptCount); Accepted → Revoked (admin, credits debited back); Revoked is terminal (re-upload refused). Pending and Accepted block new uploads.

## Validations & Rules

Upload: actor must be vendor/cashboy, leadId required, file required and must be an image; max 20 MB. MAX_REVIEW_UPLOAD_ATTEMPTS = 3 total uploads per order. Order must be Completed (not Failed). Error → HTTP: LEAD_NOT_FOUND 404, NOT_AUTHORIZED 403, NOT_COMPLETED/NO_VENDOR 422, ALREADY_PENDING/ALREADY_ACCEPTED/REVOKED/MAX_ATTEMPTS 409. Reviews: rating 1-5, text ≤2000, text mandatory for rating ≤3 (enforced in zod and again in service); duplicate review → thrown Error. getPlatformReviews zod: limit ≤100.
