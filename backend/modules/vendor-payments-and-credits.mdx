## Purpose

Vendors (partners) prepay for leads by buying "credits". One credit = ₹10 of GST-exclusive spend (credits = floor((amount / 1.18) / 10), src/services/vendorPayment/approveCredit.service.ts). Each lead assignment/lock debits credits from Vendors.creditsAvailable; a lead is only offered to a vendor whose balance covers the lead's dynamic credit cost. This module records credit purchases (manual UPI screenshot or gateway), approves them, writes the credit ledger, and notifies vendors of admin credit ops.

<Callout kind="info">Vendor credits are what the vendor pays CashKr to lock a lead. They are not part of the customer's device price. See [Device Price Lifecycle](/backend/device-price-lifecycle).</Callout>

## Core Business Logic

1.  **Credit cost of a lead.** createLead.ts getCreditPoints: Laptop/Desktop → AddCreditAlgorithm band for the price; else the device class credit. masterLead.service.ts calculateDynamicCreditPoints adds extraCredits from TierPriceSystem.getLeadPrice(vendorType, tier) (TierConfig.baseCredits + ExtraCreditRule.extraCredits). checkVendorCredit only returns a vendor whose creditsAvailable &gt;= dynamicCredits.

2.  **Debit per order.** All four assignment/lock paths (lead-assignment.service.ts, lead-reservation.service.ts, createLead.ts, masterLead.service.ts lock) call debitVendorCredits(tx, \{vendorId, amount, logs\}): a single updateMany with WHERE creditsAvailable &gt;= amount and decrement; 0 rows → throws InsufficientCreditsError which rolls back the surrounding transaction. It then writes VendorCreditLogs rows with status Debited, category OrderAssigned or OrderLocked, previous/current balance.

3.  **Buying credits (manual).** Vendor uploads a UPI screenshot via /buyCredit; row sits Pending. Approval is done from ck-admin (it reads the same DB and triggers the invoice itself).

4.  **Buying credits (gateway).** See Payment Gateway. Both gateways end in approveVendorCredit(\{paymentId, transactionId, approvedBy: "RAZORPAY" or "PHONEPE"\}).

5.  **`approveVendorCredit` (shared, idempotent).** Steps: load payment; if isApproved → already_approved no-op; duplicate-transaction guard: looks for another approved row with the same transactionId → failed ("Reject this request instead"); credits = floor((amount/1.18)/10), must be &gt; 0; one transaction: update payment (isApproved, transactionId, approvedAt, credits), log → Approved, set Vendors.creditsAvailable = previous + credits (read-then-set, not increment), insert creditOperationLogs + VendorCreditOperation (operationBy "Admin", status "Addition", label "Credit Purchase"). After commit: leaderboard cache invalidation, for gateway approvals triggerVendorInvoice(paymentId) → ck-admin internal endpoint mints the Tax Invoice, and notifyVendor(\{category: "CREDIT", title: "Credits added"\}).

6.  **Refunds / credit-backs.** This backend never writes a VendorCreditLogs row with status Credited (only reads in lib/leaderboard.ts, controllers/vendor/index.ts, OrdersMutation.ts, reviewProof). Categories OrderReversed, OrderCancelled, OrderFailedAccepted, ReviewRefund, PaymentApproved, PaymentRejected are only read here (vendor transaction history, review-refund list). Who writes them: Unclear from code — presumably ck-admin against the shared DB.

7.  **Credit value in ₹.** Purchase: ₹10 per credit before 18% GST (₹11.80 incl. GST). Minimum gateway purchase ₹10,000 → 847 credits. No ₹ value per credit is applied anywhere on the debit side (credits are abstract lead costs).

## Status / State Machine

VendorPaymentsLogs.paymentProgress: Pending → Approved (approve paths) or Rejected (gateway payment.failed / PhonePe FAILED, only if a log row exists). VendorPayments.isApproved false → true (never reverts). VendorCreditLogs.status Credited/Debited is a direction flag, not a lifecycle.

## Validations & Rules

VendorBuyCredit zod: amount non-empty string, screenShot required, vendorId uuid. Manual purchase blocked while any MANUAL_UPI row is Pending. No amount minimum on the manual path (controller) but approveVendorCredit rejects when credits would be 0. Credits formula mismatch: controller calculateExcludingGST and services/razorpay calculateCreditsFromAmount use Math.round, while approveVendorCredit and services/phonepe use Math.floor (comment in phonepe service: ₹20,000 quoted 1695, granted 1694). Debit is concurrency-safe (atomic WHERE guard).

## Background Jobs / Events

startVendorCreditNotifyJob (src/jobs/vendorCreditNotify.job.ts): cron "\*/1 \* \* \* \*" Asia/Kolkata, overlap-guarded; calls notifyPendingCreditOperations(100) which, per VendorCreditOperation with notified=false, creates a vendor inbox notification (category CREDIT, title "Credits added"/"Credits deducted", referenceType MANUAL_CREDIT/MANUAL_FINE) and sets notified=true in one transaction, then pushes FCM. Started in src/server.ts on the primary instance.
