## Purpose

The walk-in ("store") channel: a customer brings the device to a partner store; a store vendor completes the deal on the spot (no pickup, no inspection code), and the customer gets an exchange token (SMS) that is redeemed and settled against the store. Also store onboarding (KYC documents) and assigning a store vendor to a store.

## Core Business Logic (store vs pickup)

- **Pickup flow** (Lead & Nurture / Orders): customer quotes online → MasterLeads (New/Initiated) → nurture → checkout with address + pickup slot → Generated/OrderGenerated → vendor assignment/reservation/broadcast → out for pickup → inspection code (leadOtp) → requote → completion → vendor credits/payout.

- **Store flow**: customer (logged in) creates a StoreLeads row (status Generated) — no address, pickup slot, OTP, attribution, Pabbly or nurture. A store vendor completes it in one call with KYC photos, IMEI, final amount and payment type (Bank \| Buyback \| Cash) → Completed. A failed walk-in goes to FailedStoreLead with six device photos. There is no vendor credit debit, inspection timer, reschedule, or cancellation path for store leads in this code.

## Status / State Machine

StoreLeads.status: Generated (created) → Completed (complete) or Failed (failed). New exists in the enum but is never written here. ExchangeToken.status: ACTIVE → REDEEMED (redeem) / EXPIRED (verify/redeem after expiresAt) / CANCELLED (not set in this module).
