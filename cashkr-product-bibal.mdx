## 1. Company Overview

**Cashkr** is an India-based platform for selling used smartphones, laptops, Macs, tablets, and other electronics. Founded in **2020**, Cashkr started as a mobile phone buyback service and has grown into one of India's most trusted platforms for all types of consumer electronics resale.

**Mission:** To make device resale as simple, transparent, and instant as ordering food online — while promoting sustainable recycling by extending the life of electronics.

**Our Promise:**

- Instant Payouts 💰

- Verified Pickups 🚚

- Fair & Transparent Pricing 📊

- Trust Built with Every Transaction 🤝

**Company:** Operated by BigBold Technologies Pvt. Ltd.

## 3. Cashkr Website

### 3.1 Overview

The Cashkr Website (<a href="http://cashkr.com" target="_blank" rel="noopener noreferrer">cashkr.com</a>) is the public-facing entry point for device resale. It focuses on acquisition, education, and conversion into trade-in requests. The website serves three audiences: individual consumers (B2C), businesses (B2B/corporate), and SEO-driven visitors.

### 3.2 Primary User Journeys

**Consumer Device Trade-in:** Discover → Evaluate → Configure → Commit → Handoff to Customer App

**Corporate Buyback:** Discover → Review offering → Submit lead → Route to Admin Panel

**SEO Content to Qualified Session:** Search → Land on device/brand/city page → Engage → Convert to order or lead

### 3.3 Core Features

#### Login & Registration

- Phone number + OTP authentication, shared with the Customer App

- New users: collect First Name, Last Name, Email, Date of Birth after OTP verification

- Existing users: skip registration, go straight to session

- Phone number is the unique, permanent identifier

#### My Profile

- Editable: First Name, Last Name, Email

- Non-editable: Phone Number (immutable)

- Changes sync across Website, Customer App, and Admin Panel

#### Address Management

- Maximum **3 pickup addresses** per customer

- Types: Home, Office, Other

- City is auto-fetched from pincode (via Area module)

- Addresses sync across Website and Customer App

- On order confirmation, a **snapshot** of the address is stored in the order (edits don't affect existing orders)

#### Track Orders

Order statuses shown to customers: **Generated → In Progress → Completed / Failed**

- **Reschedule:** Only available when status is `Generated` and no vendor is assigned

- **Call Agent:** Only available after a vendor is assigned

#### Payment (Payout Details)

- Stored at profile level: Bank Account (Bank Name, IFSC, Account Number) or UPI ID

- Default payment mode is **Cash** if nothing is selected

- Used during payout after order completion

#### Sell Device Flow

1. Device type → Brand → Model → Variant selection

2. Serviceability check by area/pincode (blocks if unsupported)

3. Condition Q\&A (screen, battery, accessories, damage)

4. Price calculation + optional coupon

5. Pickup address & time slot selection

6. Order placement

7. Payment method selection

#### Device Price Calculator

- Instant resale estimate without creating an order

- Categories: Mobile, Laptop, Mac, Tablet

- Uses the same pricing logic as the main Sell Device flow

- Data pulled from Admin Panel: Products, Classes, Pricing

#### Search Functionality

- Universal homepage search bar with type-to-search autosuggestions

- Shows only **active products** with valid pricing and class

- Selecting a result routes directly to that device's Q\&A flow

#### Lead Creation

- Triggers when a logged-in customer reaches the final price screen but does NOT confirm an order

- Stores: selected device, Q\&A answers, pincode, customer contact info

- Appears in Admin Panel → Leads for Operations follow-up

#### Articles

- Dynamic content from Strapi CMS

- Grid/list of article cards with thumbnail, title, preview

- Real-time updates from Strapi

#### Device Finder

A dedicated device discovery section powered by Strapi, separate from the Sell flow. Covers Laptops, Smartphones, and Tablets.

**Page Types:**

- Finder Home (`/finder`)

- Category Page (`/finder/{deviceType}`)

- Brand Page (`/finder/{deviceType}/{brand_slug}`)

- Device Detail Page (`/finder/{deviceType}/{brand_slug}/{slug}`)

- Search Page (`/finder/search`)

- Compare Page (`/finder/compare`)

**Data Sources:**

- `DeviceType` collection: top-level categories (Laptop, Smartphone, Tablet)

- `Device` collection: brand, model, specs, scores, images, trending flag

**Supported Brands by Category:**

- Laptops: Apple, Acer, Asus, Dell, HP, Lenovo, Samsung, Xiaomi, and more

- Smartphones: Apple, Samsung, OnePlus, Vivo, Realme, Nothing, and more

- Tablets: Apple, Samsung, Lenovo, Xiaomi, and more

#### Refer & Earn

- Customers share a permanent referral code via WhatsApp, SMS, social media

- Referee uses the code at registration — code is locked to their account forever

- Referee reward: applied automatically at checkout after order completion

- Referrer reward: generated as pending → credited to Cashkr Wallet after admin approval

#### Partner With Us

- Static informational page for vendor partnership

- Primary CTA: Download Vendor App (links to Google Play)

#### Corporate Buyback

- Lead capture form (no login required)

- Required fields: name, phone, email, state, pincode, city, subject, query

- Submissions appear in Admin Panel → Buyback section

- Ops team manages status: In Progress → Approved → Completed

#### Logout & Account Deletion

- **Logout:** Clears session token from browser and backend; redirects to homepage

- **Account Deletion:** Requires phone + OTP verification → data anonymized → soft delete → consistent across all platforms; irreversible

## 4. Customer App

### 4.1 Overview

The Customer App gives individuals a mobile environment to manage the full device trade-in lifecycle. It shares authentication and backend services with the Website — the same identity works across both.

### 4.2 Login & Registration

- Phone number (10-digit Indian mobile) + OTP

- **New user:** registration collects First Name (required), Last Name (required), Email (required), Birthdate (optional)

- **Existing user:** logged in directly after OTP

- Session persists until explicit logout

- Cross-channel: users registered on Website can log in on App with the same phone

### 4.3 HomeScreen & Device Selection

- Device categories (Phone, Laptop, Mac, Tablet) as tappable tiles

- Promotional banners (from Admin Panel Banner module)

- Universal search bar

- Serviceability check via pincode — **blocks selling journey if not serviceable**

- Only active products with valid class & pricing shown

### 4.4 Sell Device Flow

1. Enter pincode for serviceability gate

2. Select device type → Brand → Model → Variant

3. Answer device condition Q\&A (warranty, battery, screen, physical/technical issues, accessories)

4. View quote; optionally apply coupon

5. Select or add pickup address

6. Choose pickup date & time slot

7. Confirm Order → Order created with unique Order ID → lead OTP sent to WhatsApp

8. Select payment method (UPI / Bank / Cash default)

**If the customer reaches the price screen but doesn't confirm → Lead is created in Admin Panel**

### 4.5 My Profile

- Editable: First Name, Last Name, Email

- Non-editable: Phone Number

- Synced with Website profile and Admin Panel

### 4.6 Pickup Address

- Up to 3 saved pickup addresses

- City auto-fetched from pincode via Area module

- Address snapshot copied to order on confirmation (edits don't retroactively change existing orders)

- Synced between Customer App and Website

### 4.7 Reschedule Pickup

- Available only when order status is `Generated` AND no vendor is assigned

- Hidden once order moves to `Assigned` or later

- Updated schedule syncs across all systems

- Triggers reschedule confirmation notification to customer

### 4.8 Apply Coupon

- Optional, on the final quote screen

- Platform targeting: each coupon targets Mobile, Web, or Both

- Discount is a **flat amount added** to device value (not percentage, does not stack)

- Validation checks: platform, user eligibility (first-time vs all), device type, expiry, usage limits

- Invalid coupons show inline error; price stays unchanged

### 4.9 Payment Method

- Manage UPI ID or Bank Account (Bank Name, IFSC, Account Number) at profile level

- Changes apply to future orders; completed orders retain original payment mode

- Default: Cash if no method selected

- Synced with Website Payment page

### 4.10 Order Confirmation & Tracking

**Order Statuses (Active):** Generated → Assigned → Out for Pickup → In Progress

**Order Statuses (History):** Completed, Failed

**Key Rules:**

- Reschedule: only in `Generated` with no vendor assigned

- Call Agent: only after `Assigned`

- Lead OTP sent to customer's WhatsApp on order confirmation

- Real-time status sync across Customer App, Website, Vendor App, Admin Panel

- Emails sent to customer and vendor at key status changes

### 4.11 Refer & Earn (App)

- Generate unique permanent referral code

- Share via WhatsApp, SMS, social media

- Track referred users and reward status

- Rewards: referee (instant approval), referrer (pending → admin approval → wallet)

### 4.12 Cashkr Wallet

- Stores referral reward earnings only (not device sale payouts)

- **Total Balance:** Available to withdraw

- **Total Earned:** Lifetime credited rewards

- **Total Withdrawn:** Total withdrawals to date

- **Withdrawal rules:**

  - Minimum balance: ₹100

  - Minimum withdrawal: ₹100

  - UPI only (no bank account withdrawals)

  - Manual approval by Cashkr team

  - 1 credit = ₹10

### 4.13 Lead Creation (App)

- Triggers when: user is logged in + reached final price + did NOT confirm order

- Does NOT trigger if: not logged in, pincode not serviceable, or order is confirmed

- Stored in Admin Panel → Leads with device details, Q\&A answers, pincode, contact info

### 4.14 Logout

- From Profile tab → Logout button

- Clears session token on device and backend

- Redirects to Home screen

### 4.15 Delete Account

- Profile → Settings → Delete Account

- Hands off to Website (email/deep link); app does NOT perform deletion directly

- Website handles: phone + OTP verification → anonymization → soft delete

## 5. Vendor App

### 5.1 Registration & Login

- **Registration:** Enter business details + upload documents + OTP verification → submitted for admin approval

- Vendor type is set by Admin only (not by vendor)

- **Login:** OTP-based, but only admin-approved vendors can log in

- Rejected/inactive vendors are blocked from login

### 5.2 Available Orders

Orders are shown to a vendor only if ALL four filters match:

1. **Device Type match** (phones, tablets, laptops, etc.)

2. **Pincode/Service Area match** (vendor's coverage vs customer pickup pincode)

3. **Vendor Type match** (Type 1, 2, etc.)

4. **Tier match** (vendor tier must meet order's minimum tier requirement)

### 5.3 Unlock Lead

- Vendor taps Unlock on an available lead

- System checks:

  1. **Available credits** ≥ required credits for the lead

  2. **Max Lead cap** not exceeded

- On success: credits deducted, order moves to **In Progress**; disappears from Available Orders

- On failure: no credits deducted, order stays Available

- Same customer auto-assignment: if the same customer has multiple orders, system auto-assigns to the same vendor

### 5.4 InProgress Orders

- Only orders the vendor has unlocked appear here

- Vendor actions:

  - **Call Customer** + update Call Disposition

  - **Assign to Agent** (agent sees it in their In Progress)

  - **Mark Out for Pickup**

  - **Start Inspection** (requires customer OTP verification)

  - **Requote** (re-evaluate if condition differs from declaration)

  - **Complete Order** (successful pickup)

  - **Fail Order** (condition mismatch, customer cancellation, etc.)

### 5.5 Call Disposition

Records the outcome of vendor calls: connected, not reachable, customer asked to reschedule/cancel, etc.

### 5.6 Add Agents

Vendors can add agents under their account. Agents handle pickups on the vendor's behalf and see orders assigned to them.

### 5.7 Requote Order

If device condition at pickup differs from customer's declaration, vendor can requote (adjust price). Customer can accept or decline. If declined → Fail After Requote.

### 5.8 Reserved Order

An order is Reserved when:

- A vendor already has an InProgress lead for the same customer at the same address

- Additional leads for that customer auto-link to the same vendor

- But vendor lacks enough credits to fully assign them

Once vendor adds credits and unlocks → order moves to InProgress.

### 5.9 Max Lead

The Max Lead limit controls how many active leads a vendor can hold simultaneously. Configured by admin. Reaching this limit blocks further unlocks until existing orders are completed or failed.

### 5.10 Buy Credits

- Vendors purchase credits via QR payment

- Credits become available only after **admin approval**

- 1 credit = ₹10

- Credits are deducted only on successful unlocks (not on failed attempts)

**Credit calculation:**

- **Other devices:** based on device class

- **Laptops:** based on price range; vendor type can override the base credit requirement

### 5.11 Vendor Logout

- From Vendor App profile/settings

## 7. Core Systems & Logic

### 7.1 Device Price Evaluation Logic

The pricing engine computes a final device price using a **base price minus deductions plus additions (laptops only)** formula.

**Formula:** `Final Price = Base Price − Total Deductions + Total Additions (laptops)`

**Key rule — Deduction Resolution:** All deductions use `resolveDeduction(value, basePrice)`:

- Flat value (e.g., `500` or `"500"`) → subtracted directly

- Percentage string (e.g., `"10%"`) → calculated as % of **base price** (not running total)

**Dead device:** If device doesn't turn on → return `deadPrice` immediately, skip all logic.

**Floor check:** If final price ≤ 0 → return `deadPrice` (or 0 if undefined).

#### Deduction Categories

| Code   | Category                  | Values                                                      |
| ------ | ------------------------- | ----------------------------------------------------------- |
| W1–W4  | Warranty Status           | W1 = 0–3 months (lowest), W4 = 11+ months (highest)         |
| B1–B4  | Body Condition            | B1 = Flawless, B4 = Major damage                            |
| S1–S5  | Screen Condition (Mobile) | S1 = Flawless, S5 = Heavily damaged                         |
| S1–S4  | Screen Size (Laptop)      | Size-based deduction                                        |
| P1–P4  | Physical Conditions       | Multiple can be selected; each applies independently        |
| T1–T15 | Technical Faults          | WiFi, Bluetooth, Speaker, Mic, Camera, Touch, FaceID, etc.  |
| A1–A4  | Accessories               | A1=Bill, A2=Box, A3=Charger, A4=Other — deducted if MISSING |

#### Laptop Add-ons (Additions)

- Processor (from lookup table) → adds to price

- RAM (from lookup table) → adds to price

- Storage (from lookup table) → adds to price

- Graphics Card (optional, from lookup table)

#### Supported Device Types

Mobile, Laptop, Tablet, Camera, Headphone, Console, Drone, TV, AC, Desktop, Mac, Watch

### 7.2 Tiers System

Devices are classified into three tiers:

| Tier   | Level     | Description                                                             |
| ------ | --------- | ----------------------------------------------------------------------- |
| Tier 1 | Premium   | High-demand, flagship devices (e.g., iPhone 16 Pro Max, Samsung Z Fold) |
| Tier 2 | Mid-range | Mid-segment devices                                                     |
| Tier 3 | Budget    | Budget devices                                                          |

**Impact:** Controls vendor access to orders. Vendor tier must meet order's minimum tier requirement to see it in Available Orders.

### 7.3 Credit System

- 1 Credit = ₹10

- Credits are a prepaid balance in the vendor wallet

- Deducted only on **successful** unlocks

- Purchase → QR payment → Admin approval → Available for use

- Laptop credits: based on price range (with vendor type override option)

- Credit check, Max Lead check, and order limit check are all independent gates at unlock time

### 7.4 Order Status System

**Primary Statuses:**

| Status     | Meaning                                     |
| ---------- | ------------------------------------------- |
| New        | Pre-confirmation state                      |
| Generated  | Order confirmed, awaiting vendor assignment |
| InProgress | Vendor actively working on the order        |
| Completed  | Successfully completed                      |
| Failed     | Order failed                                |
| Reserved   | On hold for vendor (insufficient credits)   |

**Secondary Statuses (more granular):** Initiated → OrderGenerated → Assigned → OutForPickup → InspectionStarted → Completed / Failed / Reserved

**Key gating rules:**

- Customer can reschedule: only in `Generated` with no vendor assigned

- Call Agent button: only after `Assigned`

- Lead OTP sent to WhatsApp: on `OrderGenerated`

- Vendor starts inspection: only after OTP verification with customer

### 7.5 Vendor Types (1–3)

Admin assigns vendor type (Type 1, 2, 3) based on submitted registration details. This controls:

- Which orders vendors can access

- Credit requirements for laptop unlocks

### 7.6 Customer Account Blocking

Admins can block customer accounts from the Admin Panel. Blocked customers cannot proceed through order flows.

### 7.7 Customer Order Flow Blocking System

System-level rules that can block customers from creating new orders based on configurable criteria (e.g., outstanding issues, fraud signals).

### 7.8 Reserved Order Feature

When a vendor has an active order for a customer and the same customer creates more orders:

- The new leads auto-link to that vendor (same customer flow)

- If vendor lacks credits → new orders go to `Reserved` status

- Once credits are added and vendor unlocks → orders move to `InProgress`

### 7.9 Body Condition Selection Logic

Customer-facing condition selection UI maps to internal condition codes (B1–B4), which map to deduction values stored in class data.

### 7.10 Device Assessment Workflow

Structured Q\&A workflow for both customers (at order creation) and vendors (at inspection). Condition answers map to device class and drive final pricing.

### 7.11 Classes System

Each device variant belongs to a **class**, which contains:

- Dead price

- Warranty deduction values (W1–W4)

- Body condition deductions (B1–B4)

- Screen condition deductions (S1–S5 or S1–S4 for laptops)

- Physical condition deductions (P1–P4)

- Technical fault deductions (T1–T15)

- Accessory deductions (A1–A4)

### 7.12 Pricing System

Admin-configured pricing per device variant and class. Prices flow dynamically to Website, Customer App, and Device Price Calculator.

### 7.13 Vendor Tier Access Control

Controls which device types (Phone, Mac, Tablet) specific vendor tiers can access and work with.

## 8. Referral & Wallet System

| Rule          | Detail                                                                   |
| ------------- | ------------------------------------------------------------------------ |

| Usage         | Each new customer can use a referral code exactly once in their lifetime |

- Status: **Approved instantly**

- Reward created after referee completes order

- Status: **Pending → Admin approval → Credited to Wallet**

### Cashkr Wallet

- Stores only referral reward earnings

- Withdrawals: UPI only, minimum ₹100, manually approved

- Completely separate from device sale payouts

## 15. Key Business Rules Quick Reference

| Rule                    | Detail                                                                    |
| ----------------------- | ------------------------------------------------------------------------- |
| Login method            | Phone number + OTP only; no passwords                                     |
| Phone immutability      | Phone number can never be changed after registration                      |
| Max addresses           | 3 per customer                                                            |
| Address snapshot        | Copied to order at confirmation; later edits don't affect existing orders |
| Default payment         | Cash, if customer doesn't select UPI/Bank                                 |
| Lead creation           | Triggered when logged-in user sees price but doesn't confirm order        |
| Coupon discount         | Flat amount added to device value; never stacks                           |
| Coupon platforms        | Each coupon targets Mobile, Web, or Both separately                       |
| Reschedule availability | Only in `Generated` status with no vendor assigned                        |
| Vendor unlock           | Requires sufficient credits AND below Max Lead cap                        |
| Credit deduction        | Only on successful unlock, never on failed attempts                       |
| Vendor type             | Set by admin only; vendors cannot select their own type                   |
| Tier system             | 3 tiers; vendor tier must meet order's minimum tier                       |
| Referral code           | Permanent; one per customer; usable once per new customer                 |
| Referral eligibility    | Phone-number based; account deletion doesn't reset eligibility            |
| Wallet withdrawals      | UPI only; min ₹100; manual approval                                       |
| Dead device pricing     | If device doesn't turn on → return configured deadPrice immediately       |
| Price floor             | If computed price ≤ 0 → return deadPrice                                  |
| % deductions            | Always calculated from BASE price, not running total                      |
