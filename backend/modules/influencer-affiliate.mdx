## Purpose

Self-contained affiliate program: each influencer has a code; customers who arrive via /r/:code (cookie) or type the code at checkout get a flat customerBonus added to their payout, and admin sees per-influencer funnel (clicks → leads → orders → completed → payout). No commission percentage exists (dropped); influencers are paid off the leaderboard numbers outside the system.

## Data Models

- Influencer (id uuid, name, contact?, platform?, code unique VarChar(64), customerBonus Int default 500 rupees, validFrom?, validUntil?, status InfluencerStatus default ACTIVE). hasMany ReferralClick, CodeRedemption, InfluencerAttribution (all onDelete: Cascade).

- ReferralClick (id, influencerId, landingPath, referrer, utm_source/medium/campaign/content/term, ipHash (HMAC of IP, never raw), device android/ios/desktop/unknown (older rows "mobile"/"tablet"), createdAt). belongsTo Influencer. Influencer only.

- CodeRedemption (id, influencerId, orderId unique = MasterLeads.leadId, customerKey HMAC of customerId, amount Int snapshot, createdAt). belongsTo Influencer. Influencer only.

- InfluencerAttribution (id, leadId unique, influencerId, code snapshot, source AttributionSource, clickId?, timestamps). belongsTo Influencer.

- MasterLeads.influencerId String? (bare, indexed; still the checkout input).

- Enums: InfluencerStatus \{ ACTIVE, PAUSED, DISABLED \}, AttributionSource \{ LINK, TYPED \}.

## Core Business Logic

1.  **ck_ref attribution**: /r/:code sets ck_ref only if isInfluencerAttributable (ACTIVE and inside validFrom/validUntil; a ₹0 bonus still attributes). At lead creation the cookie's influencerId is re-checked against the DB with the same rule; if still attributable it is stamped on MasterLeads.influencerId and mirrored to InfluencerAttribution(source=LINK, clickId=ck_ref_c). Last touch wins: a typed code overwrites a link attribution.

2.  **Validate / preview**: evaluate() → INVALID if missing, not ACTIVE, or customerBonus &lt;= 0; EXPIRED if outside the window; otherwise discount = customerBonus, finalAmount = basePrice + discount. No per-customer single-use check (per-order scope since migration 20260618).

3.  **Confirm at checkout** (confirmOrderBonuses → confirmRedemption): re-validates by influencerId and inserts CodeRedemption\{orderId, customerKey, amount\}; P2002 on orderId → returns the existing amount (idempotent). The amount is added to deviceGeneratedPrice together with the referral bonus. See [Device Price Lifecycle](/backend/device-price-lifecycle).

4.  **Release**: on vendor/cashboy fail or customer cancellation the CodeRedemption row is deleted.

5.  **Preservation**: requote adds CodeRedemption.amount back on top of the requoted price; gift-card amount does the same (or live customerBonus if no redemption yet).

6.  **Commission reporting**: there is no commission field (commissionPct dropped 2026-06-12; influencers are paid a flat amount or per user they bring). Reporting = leaderboard.query.ts SQL over InfluencerAttribution ⨝ MasterLeads ⨝ CodeRedemption: payout = SUM(deviceFinalPrice) on Completed, bonusPaid = SUM(CodeRedemption.amount) on Completed (a component of payout, not additive), conversion rates, device/UTM breakdowns.

## Status / State Machine

InfluencerStatus: ACTIVE → PAUSED → ACTIVE / DISABLED via PATCH only; no deletion. Redemption rows: created at order placement, deleted on fail/cancel.

## Validations & Rules

Codes are upper-cased and stripped to A-Z0-9; manual code min 3 chars, unique. Status must be one of ACTIVE/PAUSED/DISABLED. Owner-only and primaryStatus === "New" for apply/remove; owner-only for lead-bonus. Dedup per order only (CodeRedemption.orderId @unique). No combined cap with referral/coupon/BuyBack bonuses. ?from/?to snapped to UTC day start/end; invalid dates → 400. /:id/clicks default 30 days.
