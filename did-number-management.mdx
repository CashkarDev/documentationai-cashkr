## Overview

**Sidebar:** Vendors → Roster → **Vendor DIDs** (`/vendors/dids`) — "Dedicated Acefone numbers — the spare pool and who holds what".

Admins give each B2C vendor a **dedicated DID number**. Once assigned, calls that vendor places to customers from the Vendor App present that number as the caller ID instead of the vendor's personal mobile. Vendors without a dedicated number use the **shared DID**.

Assignment is admin-only. Vendors cannot select, request or change their own DID.

## What DID assignment controls

<Columns cols={3}>
  <Card title="What it sets" icon="phone">
    The caller ID presented to the customer when this vendor calls from the Vendor App.
  </Card>
  <Card title="Why it matters" icon="shield-check">
    Keeps the vendor's personal number private, gives customers a consistent number, and makes calls attributable for quality and disputes.
  </Card>
  <Card title="Where it impacts" icon="arrow-right">
    The Vendor App calling flow for that vendor, and admin views of vendor call activity.
  </Card>
</Columns>

## What the screen shows

### Add numbers to the pool

Paste one or more numbers separated by spaces, commas or new lines, then click **Add**. The added numbers become **Spare**.

<Callout kind="alert">
Point each number at the **Unified Call Handler** in the Acefone panel first — a number added here but not routed there will ring nowhere.
</Callout>

### Status tabs

**All**, **Assigned**, **Spare** and **Retired**, each with a count. A search box filters by number or vendor.

### Numbers table

| Column | What it shows |
| --- | --- |
| Number | The DID number. |
| State | assigned, spare or retired. |
| Vendor | The vendor holding the number (assigned numbers). |
| Since | Date the number entered its current state. |
| Notes | Optional notes. |
| Action | **Release** on assigned numbers — frees the number from the vendor. |

## Assigning a DID to a vendor

<Steps>
  <Step title="Make sure a spare exists" icon="list" title-type="p">
    On Vendor DIDs, check the **Spare** tab. If it is empty, add routed numbers to the pool first.
  </Step>
  <Step title="Open the vendor" icon="search" title-type="p">
    Go to **Vendors → Roster → All Vendors** and click the vendor row. The panel opens on the Details tab.
  </Step>
  <Step title="Use the Dedicated DID section" icon="phone" title-type="p">
    The **Dedicated DID** section shows the vendor's current number, or "No dedicated number — using the shared DID" and whether spare numbers are available in the pool. Assign a spare from here. One number maps to one vendor.
  </Step>
  <Step title="Verify" icon="check-circle" title-type="p">
    Confirm the number now shows against the vendor on Vendor DIDs, then make a test call to check the customer-facing caller ID.
  </Step>
</Steps>

<Callout kind="alert">
Always verify with a real test call after assigning or changing a number. A misconfigured routing relationship can silently fall back to behaviour that exposes a personal number, and nothing in the admin UI will show that.
</Callout>

## Operational guidance

- **Assign before going Live.** A vendor being activated should get a DID alongside pincodes and Max Leads.
- **Treat numbers as identifying.** A DID in a customer's call history points at a specific vendor. Releasing it and giving it to another vendor can connect that customer to the wrong person.
- **Record changes.** Use Notes, or your team's log, to record why a number was released or reassigned.

## Underlying integration

The feature routes through **Acefone**. The backend registers the vendor-to-customer relationship with the provider and the provider bridges the call presenting the assigned DID.

| Endpoint | Purpose |
| --- | --- |
| `POST /acefone-dialplan/create-relationship` | Registers the vendor-to-customer pairing and the DID to present. |
| `POST /acefone-dialplan/step1` | Dial-plan webhook invoked by the provider while routing. |
| `PUT /order/setCallRequest` | Records a call request against an order. |

## Known gaps

<Callout kind="alert">
Several behaviours are **not yet confirmed**, including inbound calls to the DID, whether agents share the parent vendor's number, call recording and retention, what happens to the number when a vendor goes on Hold or is Barred, and when a number moves to Retired.

The full list is on [Dedicated DID Number](/dedicated-did-number).
</Callout>
