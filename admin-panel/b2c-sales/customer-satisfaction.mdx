## Overview

**Sidebar path:** B2C Sales → OUTCOMES → **Customer Satisfaction** (`/leads/customer-satisfaction`)

Customer Satisfaction collects the ratings recorded against completed orders, so the sales and CX team can see how pickups went and follow up on bad experiences.

## Filters and search

| Control | Description |
| --- | --- |
| **Search** | By token, name, phone or vendor. |
| **All / Bad experience** | Show every rating, or only bad experiences. |
| **From / To dates** | Rating date range. Defaults to roughly the last 30 days. |
| **N shown** | How many ratings match the current filters. |

## Summary cards

| Card | Meaning |
| --- | --- |
| **Customers rated** | Number of ratings in the period. |
| **Average rating** | Average out of 5. |
| **Bad experiences** | Count of bad experiences and their share of all ratings. |

### Rating breakdown

One bar per star level (5 to 1) with the count and percentage of ratings at that level.

## What the table shows

| Column | Description |
| --- | --- |
| **Rated on** | When the rating was recorded |
| **Customer** | Customer name and order token (with copy button) |
| **Device** | Device sold |
| **Vendor** | Vendor who did the pickup |
| **Rating** | Stars, 1 to 5 |
| **Remarks** | The customer's remark or a tag such as *Vendor Issue*; — when none |
| **Recorded by** | Admin who logged the rating |

<Callout kind="info">
The screen does not say which star levels count as a **Bad experience**, or where in the panel a rating is logged. On 8 Nov 2026 the counts matched ratings of 3 stars and below, but confirm the rule with the tech team before using it in reports.
</Callout>

<Callout kind="tip">
Filter to **Bad experience** each morning and call those customers back. Group repeated remarks by vendor and raise them in [Escalations](/admin-panel/team/escalations) or the vendor's review.
</Callout>
