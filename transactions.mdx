## Overview

**Sidebar path:** Marketing → Referral Transactions (`/referral-transactions`)

The Referral Transactions page lists every reward generated by the referral system: referrer rewards that need admin approval, friend (referee) rewards paid on the friend's sale, and bonuses (such as the automatic ₹50 signup bonus).

<Callout kind="info">
Use this screen to review and approve or reject pending referrer rewards, inspect any transaction's details, and reconcile referral spend with Programs and Payouts.
</Callout>

## Summary totals

An **All time** box at the top shows three totals — they **do not** follow the tabs and filters below:

- **Waiting for approval** — total value awaiting approval.
- **Approved** — total value approved, with how many rows are automatic ₹50 bonuses.
- **Withdrawn to UPI** — total customers have withdrawn, with the number of completed payouts (see **Referral Payouts**).

A note explains how money moves: approving a referrer reward puts it in the customer's referral wallet; the ₹50 bonuses go there automatically; friend rewards are paid on the friend's sale. Wallet money only leaves when the customer withdraws on the Payouts page. Payouts are **not linked** to these rows, so nothing here is ever marked **Paid**, and Approved and Withdrawn are not expected to match.

Header buttons: **Export CSV** and **Refresh**.

## Status tabs

**All**, **Pending**, **Approved**, **Paid**, **Cancelled**, **Failed** — each with a count badge. The page opens on **Pending** (waiting for someone to approve it).

## Transaction types

| Type | When it is created | Approval |
| --- | --- | --- |
| **Referrer reward** | When the referee completes an eligible order; goes to the customer who shared the code. | Starts **Pending**; an admin must approve before it reaches the referrer's wallet. |
| **Friend reward** | When a new customer (friend) sells using a referral code; paid on the friend's sale. | Auto-approved; cannot be reversed after the order completes. |
| **Bonus** | System-triggered bonuses, e.g. the ₹50 signup welcome bonus, credited to the referral wallet automatically. | Shown as Approved when issued. |

## Table columns

| Column | What it shows |
| --- | --- |
| ☐ | Row checkbox for bulk actions. |
| **Recipient** | Customer name and phone/ID, with an **Only this customer** link that filters the list to that customer. |
| **Type** | Referrer reward, Friend reward, or Bonus, with the side it belongs to (Referrer's side / Friend's side). |
| **Amount** | INR value (sortable). |
| **Referral** | Referral code used and "from &lt;referrer&gt;". |
| **Order** | Short order (lead) ID linked to the reward, with a **Copy order ID** button. |

| **Created** | Date and time (sortable). |
| **⋮** | Row actions. |

Pagination at the bottom with a **Per page** selector.

## Filters

- **Type** chips: All types, Referrer reward, Friend reward, Bonus.
- **Exact customer ID** search.
- **Created between** — from / to dates.
- **Sort:** Newest first, Oldest first, Largest amount, Smallest amount.

## Actions

**Transaction details:** click a row to open the **Transaction details** side panel (*Who earned it, what for, and where it stands*): amount, type, status with an explanation (e.g. *Approved — credited to the customer's referral wallet*), reason (e.g. *Signup Bonus – Welcome Gift*), recipient, referral code, order (lead) ID, created and approved timestamps, transaction ID (with copy), and **Everything else the service sent**.

**Row actions (⋮):** **Approve** / **Reject** — available on **Pending** rows only.

**Bulk actions:** select one or more rows with the checkboxes to show a bar with **Approve**, **Reject** and **Clear selection**.

<Steps>
<Step title="Find pending rewards" icon="filter" title-type="p">
Open the **Pending** tab (optionally filter by **Referrer reward** and date).
</Step>
<Step title="Verify the reward" icon="search" title-type="p">
Click the row to open **Transaction details** and check the referral code, referrer, order and amount. Confirm the referee's order genuinely completed and meets the program's conditions.
</Step>
<Step title="Approve or reject" icon="circle-check" title-type="p">
Use **Approve** to credit the referrer's wallet, or **Reject** for invalid or fraudulent referrals. Rejected rewards move to **Cancelled** with the reason shown.
</Step>
</Steps>

## Status flow

1. Friend uses a code and sells → **Friend reward** created as **Approved**.
2. Referee's order completes → **Referrer reward** created as **Pending**.
3. Admin approves → **Approved** and credited to the referrer's wallet (or rejected → **Cancelled**).
4. Referrer withdraws from the wallet → processed in **Referral Payouts**. Payouts are not linked back to these rows, so they stay **Approved** (the **Paid** tab stays empty).

<Callout kind="alert">
Approvals credit the referrer's wallet immediately and are not automatically reversible. Double-check before approving, especially when using bulk approve.
</Callout>

## Connections to other modules

- **Referral Programs** — rewards follow the rules configured on the live program.
- **Referral Payouts** — approved wallet balances are withdrawn through payouts.
- **Customer app** — the referrer's wallet updates after approval.
