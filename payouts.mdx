## Overview

**Sidebar path:** Marketing → Referral Payouts (`/referral-payouts`)

The Referral Payouts page lists every withdrawal request customers raise from their referral wallet in the customer app. Admins transfer the money manually to the customer's UPI ID and record the result so wallets stay in sync with actual payouts.

Header buttons: **Upload paid file**, **Export CSV** and **Refresh**.

**Upload paid file** lets you upload a payout file with the **UTR** column filled in, to mark those payouts paid in one go (for example, the exported CSV after your bank transfers are done).

## Status tabs

**All**, **Pending**, **Approved**, **Processing**, **Completed**, **Rejected**, **Failed** — each with a count badge.

## Table columns

| Column | What it shows |
| --- | --- |
| ☐ | Row checkbox. |
| **Customer** | Customer name and phone, with **Copy customer ID** and an **Only this customer** filter link. |
| **Amount** | Amount requested (sortable). |
| **UPI ID** | Where the money should be sent. Warnings flag a **New UPI ID for this customer** or a customer **Paid to N UPI IDs**. |
| **Wallet now** | The customer's referral wallet balance **now** — not at the time of the request. |
| **Status** | Pending, Approved, Processing, Completed, Rejected or Failed. |
| **Requested** | Request date and time (sortable). |
| **UTR / Txn ref** | Transaction reference, processed time and the admin who processed it. References that don't look like a bank UTR are flagged **Not a bank reference**; **Approver not recorded** shows when no admin was saved. |

The footer shows "Showing X–Y of Z", the **₹ total on this page**, and a **Total for this filter** button.

## Filters

- **Search** by exact Customer ID (or use a row's **Only this customer** link).
- **Requested between** — from / to dates.
- **Sort:** Newest first, Oldest first, Largest amount, Smallest amount.

## Actions

Click a row to open the **Payout request** side panel (*Who asked, where the money goes, and what has been done about it*): amount, UPI ID, status, customer, wallet balance now, requested and processed times, recorded by, UTR / Txn ref (with a warning when it can't be matched to a bank statement), remarks, payout ID and customer ID.

Requests that are still open (Pending / Approved / Processing) are moved forward from the request; completed requests are view-only.

## Process a withdrawal

<Steps>
<Step title="Pick a pending request" icon="banknote" title-type="p">
Open the **Pending** tab. Check that the **Amount** does not exceed the **Wallet** balance.
</Step>
<Step title="Verify UPI ID and amount" icon="shield" title-type="p">
Open the request and confirm the UPI ID belongs to the right customer. Take extra care when the row is flagged **New UPI ID for this customer** or **Paid to N UPI IDs**.
</Step>
<Step title="Transfer manually" icon="send" title-type="p">
Send the exact amount to the UPI ID through your bank or payment gateway and keep the reference.
</Step>
<Step title="Record and complete" icon="circle-check" title-type="p">
Update the request with the bank **UTR / transaction reference** and remarks and mark it completed — or, for many payouts at once, fill the UTR column in the payout file and use **Upload paid file**. The UTR / Txn ref column then shows the reference, time and admin. Use **Rejected** for requests that should not be paid.
</Step>
</Steps>

<Callout kind="alert">
Payouts are fully manual. Double-check the UPI ID and amount before transferring — wrong payments cannot be reversed by the platform.
</Callout>

## Customer wallet context

The wallet in the customer app shows **Total Balance**, **Total Earned** and **Total Withdrawn**. The balance increases when referrer rewards are approved in **Referral Transactions** and decreases when a payout is completed. A wallet balance cannot go below zero.

## Admin responsibilities

- Process **Pending** requests promptly and keep an eye on **Processing** so nothing gets stuck.
- Only complete a payout after confirming the customer actually received the money.
- Always enter the real bank UTR as the transaction reference for audit and reconciliation — entries flagged **Not a bank reference** can't be matched to a statement.
- Use **Export CSV** for finance reconciliation.

## Connections to other modules

- **Referral Transactions** — approved rewards fund the wallet.
- **Referral Programs** — program rules decide how much customers can earn.
- **Customer app** — customers raise withdrawals and see their updated balance.
