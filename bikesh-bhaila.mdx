## Role purpose

Design clear, trustworthy, and high-converting user experiences across the Cashkr website, apps, vendor tools, and admin panel — turning business goals and user needs into intuitive screens and flows.

## Key result areas (KRAs)

- **KRA 1: Consistent and modern design system** — Create and maintain a unified design system (components, colours, typography, spacing) used across all Cashkr products.
- **KRA 2: UX for core journeys (CRO focus)** — Improve UX for critical journeys such as the sell flow (Landing → Search → Evaluation → Checkout → Order) and vendor and admin flows where operations run daily.
- **KRA 3: Problem-solving via UX** — Convert user pain points (confusion, drop-offs, complaints) into better flows, copy suggestions, and layouts.
- **KRA 4: Clean design handoffs to dev** — Provide developers (Ayaz, Resham) with clear Figma files, specs, and states so implementation is fast and accurate.
- **KRA 5: Collaboration with data and marketing** — Use insights from Ashwini’s dashboards, CX feedback, and marketing funnels to prioritise UX improvements that impact conversions and trust.

## KPIs

### Design task delivery timeliness

- **What it measures:** Percentage of design tasks delivered on or before the agreed deadline (per sprint/month).  
- **Target / direction:** Deliver on or before the agreed deadline.

### Design rework rate (due to designer-side issues)

- **What it measures:** Number of times devs ask for major redesign or clarification because the design was unclear or inconsistent.  
- **Target / direction:** Aim to keep low.

### Adoption of design system

- **What it measures:** Percentage of new features/pages using standardised components from the design system (vs custom one-off UI).  
- **Target / direction:** Increase adoption of the design system over time.

### UX issue volume (UI/UX complaints)

- **What it measures:** Number of UX-related complaints raised by CX/Ops/users on major flows.  
- **Target / direction:** Should reduce over time as UX improves.

### Experiments / UX improvements shipped per month

- **What it measures:** Count of UX changes or experiments designed and implemented (for example, new layout, trust section, FAQ pattern, CTA changes).  
- **Target / direction:** Maintain a healthy, consistent number of improvements shipped each month.

### Handoff quality (dev feedback score)

- **What it measures:** Simple internal rating from devs monthly (1–5) on clarity of design handoffs.  
- **Target / direction:** Keep scores high and improve over time.

### Documentation and update frequency (design system)

- **What it measures:** How often the design system and components are updated and documented when new patterns are introduced.  
- **Target / direction:** Keep documentation current and update promptly when new patterns are introduced.

## Core processes / SOPs owned

Bikesh is owner or co-owner of these UX/design SOPs:

- **Design system and UI components SOP**
  - Rules for colours, typography, spacing, buttons, inputs, cards, states, icons, empty states, and error states.
  - How new components are added and old ones updated.

- **UX flow design SOP**
  - How user journeys are mapped (for example, lead → order, vendor onboarding, admin workflows) before designing screens.
  - Using simple user flows and wireframes before high-fidelity UI.

- **Design handoff SOP**
  - How Figma files are structured (pages, components, naming).
  - What devs receive: specs, spacing, responsive behaviour, states (normal/hover/disabled/error), assets.
  - How comments and clarifications are handled.

- **Feedback and iteration SOP**
  - How feedback from CX, Ops, Marketing, CEO, and users is collected, prioritised, and converted into UX tasks.

- **Cross-platform consistency SOP**
  - Ensuring web, app, vendor, and admin all feel like the same brand and follow consistent patterns (navigation, buttons, error messages, and similar elements).

- **Data-informed UX SOP**
  - How Bikesh works with Ashwini to use funnel data, heatmaps (later), and drop-off reports to decide what UX to improve first.

## Weekly & monthly reporting

### Weekly reporting

- **To:**  
  - IT Manager – Shahid  
  - With visibility to: Ibrahim, Pranjal, Ayaz, Resham, Nirajan, Ashwini (as needed)

- **Format:** Short update in Slack or Notion.

- **Includes:**
  - Designs completed this week  
    - Screens/flows for web, app, vendor, admin.
  - UX problems addressed  
    - For example, clarified final price screen, improved evaluation flow layout.
  - Pending clarifications  
    - Decisions needed from Shahid, CEO, or Marketing.
  - Next week focus  
    - Top UX areas to work on (for example, homepage hero, FAQ pattern, vendor dashboard).

### Monthly reporting

- **To:**  
  - Shahid  
  - Ibrahim (CEO)  
  - Marketing Head (Pranjal)  
  - Other leads as needed

- **Format:** 1–2 slides or short section in monthly review.

- **Includes:**
  - Major UX improvements shipped this month  
    - Before/after explanation for key flows if possible.
  - Design system updates  
    - New components, patterns, guidelines added.
  - Feedback summary  
    - Common UX issues raised and how they were solved or planned.
  - Next month’s UX priorities  
    - Which flows or parts of the product will be redesigned or optimised.
