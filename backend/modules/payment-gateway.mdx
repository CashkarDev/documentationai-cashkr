## Purpose

Instant online top-up of vendor credits. PhonePe (fee default 1.5%) is the primary gateway with an automatic Razorpay fallback (fee from RAZORPAY_FEE_PERCENT, documented 2.5%); both auto-approve credits through approveVendorCredit. The same PhonePe service is reused by the ckwipe license purchase flow.

## Core Business Logic

1.  **Amounts.** creditAmount = what the vendor selects (₹, GST-inclusive). Charge = creditAmount + round(creditAmount × fee%). PhonePe fee PHONEPE_FEE_PERCENT default 1.5; Razorpay fee RAZORPAY_FEE_PERCENT **required** (throws if unset). VendorPayments.amount stores creditAmount (not the inflated total); gatewayFee stored separately. Credits quoted = floor((creditAmount/1.18)/10) for PhonePe, round(...) for Razorpay service.

2.  **Unified initiate (`initiatePaymentWithFallback`).** Primary from PAYMENT_PRIMARY_PROVIDER (default PHONEPE; RAZORPAY skips PhonePe with no reverse fallback). PhonePe path: generate merchantOrderId → createSdkOrder (APP) or createWebCheckoutOrder (WEB, QA) → insert pending row. On a *gateway* error only (network codes, HTTP 502/503/504, timeouts): call getOrderStatus(merchantOrderId); status API down → 503 PHONEPE_STATUS_API_DOWN; COMPLETED → insert PHONEPE row, return alreadyCompleted (controller then approves credits); PENDING → 409 PHONEPE_PAYMENT_PENDING; FAILED/other → Razorpay order with fallbackReason. Razorpay failure → 503 PAYMENT_GATEWAYS_UNAVAILABLE (QA tools can return a mock order). Non-code errors are hidden behind a generic 500 message.

3.  **Verification / idempotency.** Razorpay: client signature check races the webhook; both call approveVendorCredit, which is idempotent per paymentId (already_approved) and guards duplicate transaction ids across rows. Unique DB columns on razorpayOrderId, razorpayPaymentId, phonepeMerchantOrderId prevent duplicate rows; a P2002 on the pre-approval update is tolerated. PhonePe: no client signature — the backend is the source of truth via Order Status API; webhook validated by the SDK.

4.  **Reconciliation (PhonePe only).** reconcilePendingPhonePePayments polls unapproved PHONEPE rows aged between floorMinutes and maxAgeHours, ordered by updatedAt asc, batch batchSize; skips rows whose persisted gatewayResponse.state === "FAILED"; backoff by age via nextPollIntervalMinutes (&lt;30 min: 5; &lt;6 h: 15; &lt;24 h: 60; &lt;48 h: 240; else drop), using updatedAt as the last-check clock. COMPLETED → same update + approveVendorCredit(... "(reconciled)"); FAILED → markPhonePeFailed; PENDING → persist status (bumps updatedAt), warn if older than alertAfterHours. Transient errors do not bump updatedAt.

5.  **Refunds.** refundPayment(paymentId) (paymentGateway.service.ts): RAZORPAY → razorpay.payments.refund(razorpayPaymentId, \{speed: "normal"\}); PHONEPE → manual_required (dashboard); MANUAL_UPI → failed. **No caller in src** (dead code).

6.  **Business flows using payments.** Vendor credit top-up (this module). ckwipe license purchase. Gift cards are *issued* via Woohoo SVC balance, not paid by a customer gateway. No customer-side payment gateway exists in this repo.

## Status / State Machine

No dedicated status column; derived: isApproved=true → success; VendorPaymentsLogs.paymentProgress === "Rejected" → failed; else pending. PhonePe states from SDK: PENDING \| COMPLETED \| FAILED. Razorpay webhook events handled: payment.captured, payment.failed. PhonePe callback types handled: CHECKOUT_ORDER_COMPLETED, PG_ORDER_COMPLETED, CHECKOUT_ORDER_FAILED, PG_ORDER_FAILED.

## Validations & Rules

amount must parse to a positive integer and be ≥ 10,000 (all three createOrder paths). Razorpay signatures compared with crypto.timingSafeEqual. Webhook returns 400 for bad signature, 200 for unknown orders/events (to stop retries), 500 only on exceptions. QA tooling (PAYMENT_QA_TOOLS) fails closed when NODE_ENV=production. PHONEPE_SIMULATE_DOWN=true simulates a PhonePe outage for testing.
