## Overview

The Reserved page in Orders - B2C displays all orders that have been reserved for a specific vendor. Admins use this page to monitor reserved orders and ensure they are being acted upon by the intended vendor.

<Callout kind="info">
  A reserved order is locked to one specific vendor. Only that vendor can see and act on the order until an admin removes the reservation.
</Callout>

## What the Reserved page shows

Each row in the Reserved list represents one order that has been reserved for a specific vendor. The table columns match other order views and include:

- **Created At** — Date and time the order was created.
- **Model** — Device model the customer wants to sell.
- **City** — City where the pickup is scheduled.
- **Type** — Device category: Mobile, Laptop, Tablet, or Mac.
- **Status** — Current status of the reserved order.

When no reserved orders are present, the page displays a `No Orders Found` message indicating there are currently no orders matching the reserved criteria.

## What Reserved means

A reserved order is one that has been locked to a specific vendor, restricting visibility and actions on that order.

- Only the **reserved vendor** can see and act on the order in their vendor app.
- Other vendors in the same pincode **cannot see or accept** this order.
- The order stays reserved until the reserved vendor completes it or an admin removes the reservation.

Reserved orders are typically created when:

- A customer specifically requests a particular vendor for their pickup.
- An admin manually reserves an order for a trusted or preferred vendor in that area.
- A vendor has a prior relationship or commitment with the customer for that order.
- An order was previously assigned, fell through, and needs to be directed to a reliable vendor.

<Callout kind="alert">
  Reservations limit visibility to one vendor. Overusing Reserved can slow down pickups and reduce order coverage across your vendor network.
</Callout>

## Filters and controls

Use filters and search controls to focus on the reserved orders that matter for your review.

- **Device Type Filter** — Filter reserved orders by device category: Mobile, Laptop, Tablet, or Mac.
- **City Filter** — Filter reserved orders by the city where the pickup is scheduled.
- **From Date / To Date** — Filter orders by their creation date range.
- **Show Orders with Test Accounts** — Toggle to include or exclude orders created with test accounts.

<Callout kind="alert">
  Uncheck **Show Orders with Test Accounts** for normal operations so you see only real customer orders. Use it only when you explicitly need to review test data.
</Callout>

- **Search** — Search for a specific reserved order by order details, device name, or customer information.
- **Apply Filters** — Apply the selected filters to update the Reserved list.
- **Reset** — Clear all filters and return to the full Reserved orders list.

## Admin actions on Reserved orders

For orders listed in the Reserved page, admins can:

- Monitor whether the reserved vendor is acting on the order in a timely manner.
- Contact the reserved vendor directly if the order is sitting idle.
- Remove the reservation and reassign the order to a different vendor if the reserved vendor is unable to complete the pickup.
- Open the order detail to see which vendor the order is reserved for and when it was reserved.
- Escalate to operations if a reserved order becomes delayed.

## Reserved order flow

### Main flow when the reserved vendor acts

<Steps>
  <Step title="Order created or converted" icon="download">
    The order is created by the customer or converted from a lead and enters the Orders - B2C pipeline.
  </Step>
  <Step title="Admin reserves the order" icon="settings">
    An admin reserves the order for a specific vendor, locking it to that vendor only.
  </Step>
  <Step title="Order appears in Reserved" icon="monitor">
    The order now shows in the Admin Panel Reserved view and in the reserved vendor's app.
  </Step>
  <Step title="Vendor sees order exclusively" icon="users">
    The reserved vendor sees the order in their vendor app. No other vendor in the same pincode can view or accept it.
  </Step>
  <Step title="Vendor completes the pickup" icon="check-circle">
    The reserved vendor completes the pickup, updates the order status, and moves it out of Reserved into the normal completion flow.
  </Step>
  <Step title="Device enters All Inventory" icon="package">
    After completion and device receipt, the order leaves the Reserved flow and the device appears in All Inventory.
  </Step>
</Steps>

### Alternate flow when the reserved vendor does not act

<Steps>
  <Step title="Reserved order shows no progress" icon="alert-triangle">
    The order remains in Reserved without action or status movement from the assigned vendor.
  </Step>
  <Step title="Admin reviews the Reserved page" icon="search">
    An admin checks the Reserved list to identify idle or delayed orders and confirms the assigned vendor and reservation time.
  </Step>
  <Step title="Admin removes or changes reservation" icon="edit">
    The admin removes the reservation or reassigns the order to another vendor based on operational needs.
  </Step>
  <Step title="Order moves to new section" icon="arrow-right">
    After removing or changing the reservation, the order moves to the appropriate section based on its new status, exiting the Reserved view.
  </Step>
</Steps>

<Callout kind="alert">
  If a reserved vendor becomes unavailable or unresponsive, remove the reservation immediately so the order does not become unnecessarily delayed.
</Callout>

## Admin responsibilities

Admin responsibilities for the Reserved page include:

- Check the Reserved page regularly so reserved orders are not sitting idle.
- Act immediately if a reserved order shows no progress from the assigned vendor.
- Remove reservations that are no longer relevant to open the order back up to all vendors in the area.
- Use reservations carefully and only when there is a genuine operational or customer-driven reason to restrict an order to one vendor.
- Ensure the reserved vendor is informed and available before placing a reservation.

## Connections to other modules

Reserved interacts with several other Admin Panel and vendor flows:

- **In Progress** — Once the reserved vendor acts on the order, it moves to In Progress.
- **Vendors - B2C** — The vendor the order is reserved for must be live and have the relevant pincode and device type assigned.
- **Delayed** — If a reserved order crosses its pickup date without completion, it also appears in the Delayed section.
- **No Action** — If the reserved vendor takes no action after assignment, the order may also appear in No Action.
- **All Inventory** — After the reserved order is completed and the device received, it enters All Inventory.
