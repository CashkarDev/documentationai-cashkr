## Overview

**Sidebar:** Vendors → Roster → **Vendor Tiers** (`/settings/tier-config`). Page title: **Tier Management** — "Configure tiers, vendor types, access rules, and extra credit charges".

Vendor tiers control which device orders a vendor can see. Each vendor is given a **vendor type**; each vendor type has access to one or more **tiers**; each order carries the tier of its device model. A vendor only sees an order when their vendor type has access to that order's tier.

<Callout kind="info">

Device tiers belong to device models, not to vendors:

- Each device model is assigned to exactly one tier based on its demand and brand level.
- Each customer order carries the tier of the selected device model.
- Each vendor has a vendor type. Vendors only see orders in `Available Orders` for tiers their vendor type can access.

</Callout>

The screen has three tabs: **Vendor Types**, **Access Matrix** and **Extra Credits**.

## Vendor Types

"Add and manage vendor type classifications."

| Column | What it shows |
| --- | --- |
| Type Number | Type badge, for example Type 1. |
| Name | Display name (for example Gold Vendor, Silver, Bronze Vendor). |
| Description | Short description of what the type can pick. |
| Accessible Tiers | Tier chips the type can access (Tier 1, Tier 2, Tier 3). |
| Actions | Delete (bin icon). |

**Add Vendor Type** opens a dialog ("Create a new vendor type classification") with:

- **Type Number** — prefilled with the next free number.
- **Name** — e.g. "Type 6 - Enterprise Partner".
- **Description** — "Describe this vendor type…".

Click **Create Type** to save or **Cancel** to close. Tier access for the new type is set on the Access Matrix tab.

## Access Matrix

"Configure which vendor types can access which tiers (click to toggle)."

- Rows are vendor types (name and type number).
- Columns are tiers, each showing its base credit cost (for example Tier 1 · 100 credits, Tier 2 · 70 credits, Tier 3 · 30 credits).
- A ticked cell means that vendor type can access that tier. Clicking a cell toggles access.

<Callout kind="alert">

Toggling a cell changes order visibility for every vendor of that type immediately. Double-check before clicking.

</Callout>

## Extra Credits

"Configure extra charges for specific vendor type + tier combinations." Use this when a vendor type should pay more (or less) than the tier's base credits.

| Column | What it shows |
| --- | --- |
| Vendor Type | The vendor type the rule applies to. |
| Tier | The tier the rule applies to. |
| Extra Credits | Added credits, for example +50 credits. |
| Reason | Optional explanation. |
| Actions | Edit (pencil) and delete (bin). |

**Add Rule** opens **Add Extra Credit Rule** with:

- **Vendor Type** — select from existing vendor types.
- **Tier** — Tier 1 (Premium), Tier 2 (Mid-Range) or Tier 3 (Budget).
- **Extra Credits** — "positive = charge, negative = discount".
- **Reason (Optional)** — e.g. "Premium service charge".

Click **Create Rule** to save or **Cancel** to close.

## How tiers work (reference)

- Tiers for device models are based on **market demand and brand level**. Higher-value models sit in higher tiers.
- Each device model belongs to **exactly one tier**, which becomes the tier of any order for that model.
- Each vendor is assigned a **vendor type** on their profile in [Vendors - B2C](/b2c-vendors); the type's accessible tiers decide what they see.
- Unlock cost = the tier's base credits plus any matching extra credit rule for the vendor's type.

For more on how device tiers are defined, read [Tiers System](/tiers-system).

## Common troubleshooting checks

### Vendor says "I cannot see this order"

- Confirm the **device model's tier** for that order.
- Check the vendor's **Vendor Type** in their profile on All Vendors.
- On the **Access Matrix**, confirm that vendor type has access to that tier.
- If it does not, the behaviour is correct. If it does and the order is still missing, check other constraints (pincode, device type, Max Leads, status) in [Available Orders](/available-orders).

### Vendor is charged more credits than expected

- Check the tier's base credits in the Access Matrix header.
- Check the **Extra Credits** tab for a rule matching the vendor's type and the order's tier.

### Orders are going to the wrong kind of vendors

- Review whether the **device model is mis-tiered**. A tier that is too low exposes orders to too many vendors; too high limits routing and slows pickup.
- Review the Access Matrix — a vendor type with more tiers than intended sees more orders.
- Fix mis-tiering at the device model level so future orders follow the right rules.
