## Purpose

Refer-a-friend: a customer shares a code/link; the referee gets a payout bonus on their first order and the referrer earns a wallet reward that admin approves and pays out via UPI. The program, codes, referrals, wallet, transactions and withdrawals live in a SEPARATE referral microservice (REFERRAL_SERVICE_URL); this backend proxies, stamps referralId on orders, computes the referee bonus at checkout, and fires webhooks/notifications.

## Data Models (this DB)

- MasterLeads.referralId String? (bare, indexed) — the referral service's referral id stamped on the referee's lead.

- ReferralProgram (id, name, description, code unique, rewardAmount Int, rewardType default "CASH", minTradeValue, isActive, startDate, endDate) — present in schema but NO code in src/scripts reads or writes it (legacy/unused; the live program config is in the microservice).

- Page (id, key unique, name, icon, parentKey, sortOrder, isActive) hasMany AdminPermission — prisma/seed-referral-pages.sql upserts admin nav pages referral-programs, referral-transactions, referral-payouts.

- ReferralClick and CodeRedemption belong to the Influencer module, NOT to this referral program.

- Wallet / transaction / withdrawal tables: none in prisma/schema.prisma. They live in the referral microservice.

## Core Business Logic

1.  **Code generation / share link**: entirely in the microservice (POST referral-codes). Share URL www.cashkr.com/app?referral-code=… is handled by the App Link module (/app-open), see docs/referral-share-link.md.

2.  **Signup attribution**: registerUser.ts fires sendReferralWebhook('customer-created', \{customerId, phone, email, firstName, lastName, referralCode?\}). The service creates a PENDING referral when the code resolves.

3.  **Click attribution**: none in this backend for the referral program (no click table; ReferralClick is influencer-only).

4.  **Checkout preview**: Lead/index.ts (lead creation) queries \{RS\}/referrals/my-referrals for a PENDING referral of a first-order customer, stamps MasterLeads.referralId, fetches \{RS\}/referral-programs/active, and stores the original order amount via \{RS\}/referrals/:id/original-order-amount. GET /api/v1/influencer/lead-bonus shows the combined influencer + referral bonus using previewOrderBonuses.

5.  **Referee bonus at order placement**: createLead.completeLead → confirmOrderBonuses → computeRefereeDiscount (referralDiscount.service.ts) re-derives the amount on the server from the active program's referee config (flat, or PERCENT with maxDiscount and minOrderValue). The result is ADDED to deviceGeneratedPrice. Requote preserves it via getGrantedRefereeDiscount (server-to-server). See [Device Price Lifecycle](/backend/device-price-lifecycle).

6.  **Reward crediting on completion**: when the order becomes Completed and it is the customer's FIRST completed order and referralId is set → sendReferralWebhook('order-completed', \{orderId, customerId, referralId, orderAmount (deviceGeneratedPrice), finalAmount (deviceFinalPrice), status:'COMPLETED'\}). This only makes the referrer reward PENDING in the service.

7.  **Admin approve/pay**: admin approves the transaction (proxied). The service then calls back POST /api/v1/referral/internal/credited → WhatsApp + Pabbly list. Withdrawals: customer requests via /wallet/withdraw (amount + UPI id); admin process (UPI payout) or reject; customer may cancel. Actual money movement is inside the service (Unclear from this code).

8.  **Wallet balance**: proxied GET /wallet; sync script/endpoint gives existing customers a ₹50 signup wallet (per script header).

## Status / State Machine

Referral statuses seen in code: PENDING (and "completed/cancelled" mentioned in Lead/index.ts). Transaction/withdrawal statuses are owned by the microservice — Unclear from code.

## Validations & Rules

/wallet/withdraw: amount &gt; 0, upiId non-empty. /apply: code required; discount must be valid per service. completed-orders-count supports the service's minCompletedOrders rule. ipAddress and userAgent are forwarded on /apply for the service's checks. All service calls have 5 s timeout (10 s for generate) and never block order flows.

## Background Jobs / Events

No cron. Outgoing webhooks: customer-created, order-completed. Incoming callback: /internal/credited. Meta CAPI event ReferralRewardCredited at admin approval only (not at completion, to avoid dedup clash on reward\_&lt;orderId&gt;).
