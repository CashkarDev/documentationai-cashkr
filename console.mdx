## Console overview

The Console page (**Console Management**, route `/console`) in **Admin Panel → Devices** manages all gaming console models available for buyback. It has four tabs: **Models**, **Brands**, **Classes**, and **Pricing**, using the shared device layout described on the [Phone](/phone) page.

Console devices use the `mobilePriceEvaluation` strategy with condition groups for age (`W1`–`W4`), body (`B1`–`B3`), physical or functional issues (`P1`–`P6`), and accessories (`A1`–`A3`). Consoles do not use battery, screen, or technical fault codes.

Console pricing also supports two console-specific additions: number of CDs/games (`CD1`–`CD10`) and extra controllers (`E1`–`E8`). These add value to the evaluated price. Console is one of only two device types, alongside Camera (extra lenses), where additions can push `finalPrice` above `basePrice`.

<Tabs>
  <Tab title="Models" icon="package">

  ## What you see

  The Models tab lists console models, 20 per page.

  | Column | Description |
  | --- | --- |
  | Checkbox | Select rows for bulk actions |
  | Model | Image, model name, and brand • URL slug |
  | Code | Unique model code, for example `CMIC0001` |
  | Price | Base buyback price |
  | Class | Assigned pricing class |
  | Actions | Row menu |

  Consoles have no variants, so there is no Variants column or expand chevron. Examples include Xbox 360, Xbox Series X, PS3, PS4, and PS5 models.

  ## Search and filters

  Use **Search models…** with **Filter**, the **All Brands** dropdown (Microsoft, Sony), and the refresh icon.

  ## Row actions

  **Edit Model**, **View SEO**, **Duplicate**, and **Delete**.

  ## Add

  <Steps>
    <Step title="Open the form" icon="plus">

    Click **Add Model** ("Add a new console model").

    </Step>
    <Step title="Basic Info" icon="edit">

    Select **Brand***, enter **Model Name*** (for example `PlayStation 5 Slim`), and add an **Image** (URL or Upload). There are no Series, Storage, or RAM fields.

    </Step>
    <Step title="URL & Code and SEO" icon="link">

    Generate or enter the **Base URL** and **Model Code**. Use **Auto-Generate SEO** or fill Page Title, Page Description, H1 Heading, and Image Alt Text.

    </Step>
    <Step title="Pricing" icon="bar-chart">

    Enter **Base Price (₹)*** and choose the **Pricing Class***. The class controls how age, body, functional condition, accessories, CDs, and controllers affect the final price.

    </Step>
    <Step title="Save the model" icon="check-circle">

    Click **Create Model**.

    </Step>
  </Steps>

  <Callout kind="alert">

  Delete a model only after confirming it is not needed in current evaluation or catalog workflows.

  </Callout>

  </Tab>

  <Tab title="Brands" icon="book-open">

  ## What you see

  The Brands tab lists console manufacturers: **Microsoft** and **Sony**. Columns are Brand ID, Brand Name, Device Type, Brand Link, Brand Image, and Title.

  Search, Filters, **Add New Product** (Add New Brand dialog: Brand Name, Device Type, Brand Link, Title, Description, Brand Image), and Brand Details (Edit, Delete) work as on the Phone Brands tab. Set **Device Type** to Console.

  <Callout kind="alert">

  Reassign dependent models before deleting a brand.

  </Callout>

  </Tab>

  <Tab title="Classes" icon="shield">

  ## What you see

  The **Console Classes** table has five classes (A–E). A class defines the credit, dead price, tier, and every deduction or addition used during console evaluation.

  | Group | Codes | Options | Effect |
  | --- | --- | --- | --- |
  | Warranty | `W1`–`W4` | 0–3, 3–6, 6–11, 11+ months | Deduction |
  | Body | `B1`–`B3` | Scratchless, Average, Below Average | Deduction |
  | CDs / Games | `CD1`–`CD10` | 1 CD … 10 CDs | Addition |
  | Extra Controllers | `E1`–`E8` | 1 … 8 controllers | Addition |
  | Physical | `P1`–`P6` | CD Drive Not Working, USB / Charging Port Not Working, HDMI Output Port Not Working, LAN Port Not Working, Bluetooth Not Working, WiFi Not Working | Deduction |
  | Accessories | `A1`–`A3` | Bill, Box, Cables | Deduction |

  <Callout kind="info">

  Current console classes store these values as flat rupee amounts. The class form itself accepts either a flat amount or a percentage ("e.g. 500 or 10%"), so enter rupee values to keep console classes consistent.

  </Callout>

  ## Search and filters

  Use **Search classes… (press Enter)** and the sortable Class Type, Credit, Dead Price, and Tier columns.

  ## Add

  <Steps>
    <Step title="Open the form" icon="plus">

    Click **Add New Class** ("Create a new pricing model for Console devices"). Tabs: Basic Info, Warranty, Body, CDs / Games, Controllers, Physical, Accessories.

    </Step>
    <Step title="Basic Info" icon="edit">

    Enter **Class Type***, **Tier**, **Credit**, and **Dead Price** (the minimum fallback price).

    </Step>
    <Step title="Deductions" icon="edit">

    Fill **Warranty** (`W1`–`W4`), **Body** (`B1`–`B3`), **Physical** (`P1`–`P6`), and **Accessories** (`A1`–`A3`).

    </Step>
    <Step title="Additions" icon="plus">

    Fill **CDs / Games** (`CD1`–`CD10`) and **Controllers** (`E1`–`E8`) with the value each count adds.

    </Step>
    <Step title="Save the class" icon="check-circle">

    Click **Create Class**. The class becomes available for console models.

    </Step>
  </Steps>

  ## Edit, delete, export

  Use the row menu to **Edit** or **Delete**. Reassign every dependent model before deleting a class. **Export CSV** downloads the class table for offline review of `W`, `B`, `P`, `A`, `CD`, and `E` values.

  </Tab>

  <Tab title="Pricing" icon="bar-chart">

  ## What you see

  The Console Pricing tab uses the shared layout: Pricing Overview, BuyBack bonus and Bulk bonus, Filters, All Brands, search, Export, and Import. Each row shows Model, Specs, Class (dropdown), Base Price (✎), Bonus, and the **3-6 Months**, **6-11 Months**, and **11+ Months** prices with their % change. The row menu has **Price History**. Select rows to use **Update Price** or **Update Class** in bulk.

  ## Deduction and addition groups

  | Group | Codes | Effect on price |
  | --- | --- | --- |
  | Age | `W1`–`W4` | Deduction |
  | Body | `B1`–`B3` | Deduction |
  | Physical or functional | `P1`–`P6` | Deduction |
  | Accessories | `A1`–`A3` | Deduction for missing accessories |
  | CDs / Games | `CD1`–`CD10` | Addition |
  | Controllers | `E1`–`E8` | Addition |

  <Callout kind="alert">

  Do not confuse `P1` (CD Drive Not Working, a deduction) with `CD*` codes (number of CDs/games, an addition).

  </Callout>

  ## Formula

  ```text
  finalPrice = basePrice - age(W) - body(B) - functional(P) - missingAccessories(A) + CDs(CD*) + controllers(E*)
  finalPrice = max(finalPrice, deadPrice)
  ```

  A console's final price can end higher than its `basePrice` when CD and controller additions exceed the deductions. That is expected.

  ## Edit

  Change the model's base price (inline ✎ or in Edit Model) when only the starting price changes. Change the class values when the deduction or addition logic changes. Review addition values after every change, because small updates can materially change final offers.

  <Callout kind="alert">

  If you remove class values or assign the wrong class, console evaluations can return incorrect final prices.

  </Callout>

  </Tab>
