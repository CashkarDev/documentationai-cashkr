## Overview

**Sidebar path:** Marketing → Push Notifications (`/notification`)

The **Push Notification Hub** lets admins send, schedule, and manage push notification campaigns for the **Customer App** (Cashkr users) and the **Vendor App** (partner vendors). Each tab is reachable directly through the URL, for example `/notification?tab=history`.

## Tabs

| Tab | What it is for |
| --- | --- |
| **Compose** | Write a one-off notification, choose app and audience, send now or schedule. |
| **Campaigns** | Create and manage multi-step campaigns (one-time, drip, recurring, A/B test). |
| **Templates** | Reusable notification content with dynamic variables. |
| **Segments** | Reusable audience definitions built from filter conditions. |
| **Analytics** | Delivery performance and outcomes for a selected period. |
| **History** | Log of every notification sent, with status and delivery counts. |
| **Scheduled** | Notifications queued for a future date and time. |

## Compose tab

The left side holds the **Compose Notification** form; the right side shows a **Live Preview**.

| Field | Details |
| --- | --- |
| **Title** \* | Counter shows `0/50` — keep it under 50 characters so it isn't cut off. |
| **Body** \* | Counter shows `0/120` — keep it under 120 characters so it isn't cut off. |
| **Banner Image** (optional) | Upload an image or paste its URL. JPG or PNG under 1 MB, roughly 2:1. Shown large only when the reader expands the notification. |
| **Target App** \* | **Customer App** (Cashkr users) or **Vendor App** (partner vendors). One app per notification. |
| **Audience** \* | **All Users**, **Topic** (enter a topic name, e.g. offers, updates) or **Specific Users** (paste customer/vendor IDs separated by commas). |
| **Schedule for later** | Toggle on to show **Date** and **Time (IST)** pickers. |

The submit button reads **Review & send**, or **Review & schedule** when scheduling is on. It opens a review step before anything is sent.

### Live preview

- Switch between **Android** and **iPhone** mock-ups.
- Switch between **Collapsed** (how it first appears — truncation depends on the phone) and **Expanded** (shows the banner image).
- A summary below shows the selected **Target App** and **Audience** (e.g. *Not Chosen Yet*, *Topic*, *Individual*).

<Callout kind="alert">
Sent notifications cannot be recalled. Double-check the **Target App** and **Audience** before confirming — sending a customer promotion to the Vendor App (or vice versa) is the most common mistake.
</Callout>

## Campaigns tab

Lists campaigns as cards showing name, status badge (e.g. **Active**, **Paused**), type badge (e.g. **One-time**), and **Sent** / **Delivered** counts.

**Filters:** search box, **Status** (All Status, Draft, Active, Paused, Completed), **Type** (All Types, One-time, Drip, Recurring, A/B Test), and a refresh button.

**Row actions (⋯ menu):** **Pause** for an active campaign, **Resume** for a paused one. The arrow opens the campaign.

**New Campaign** opens a 5-step wizard: **Basics → Audience → Content → Schedule → Review**. The Basics step asks for:

| Field | Details |
| --- | --- |
| **Campaign Name** \* | e.g. *Welcome Series* |
| **Description** | What the campaign is about. |
| **Goal** | e.g. *Increase app opens, Re-engage dormant users*. |
| **Target App** | Customer or Vendor. |
| **Campaign Type** | **One-time** (send once to audience), **Drip Series** (multi-step automated sequence), **Recurring** (daily, weekly, or monthly), **A/B Test** (test different variants). |

## Templates tab

Cards show template name, title and body, deep link (if any), and how many campaigns use it. A **Test-site link** badge flags templates whose link points to a test/staging site — fix these before using them in production.

**Filters:** search, **All Apps** (Customer/Vendor), refresh.

**Card actions:** **Edit**, **Duplicate**, and **Delete** (in the ⋯ menu).

**New Template** form:

| Field | Details |
| --- | --- |
| **Active** | Toggle whether the template is available. |
| **Template Name** \* | Internal name. |
| **Target App** | Customer or Vendor. |
| **Available Variables** | `{{firstName}}`, `{{lastName}}`, `{{fullName}}`, `{{city}}`, `{{phone}}`, `{{email}}` — click to insert into the body; type manually for the title. |
| **Notification Title** \* | Up to 255 characters. |
| **Notification Body** \* | Message text. |
| **Image URL** (optional) | Image shown with the notification. |
| **Deep Link** (optional) | The screen users see when tapping, e.g. `/myorders`, `/sell/mobile`. |

A phone preview updates as you type. Save with **Create Template**.

## Segments tab

Lists saved audience segments with search, **All Apps** filter, and refresh. When empty, use **Create Segment**.

**New Segment** form:

- **Details:** **Name** \* (e.g. *Mumbai Customers*), **Description**, **Target App** (Customer / Vendor), **Filter Logic** (**Match ALL** or **Match ANY**).
- **Filter Conditions:** pick a field — **City**, **Registration Date**, **Has Push Token**, **Is Blocked**, **Email**, **Phone**, **Pincode** — operator **equals**, and a value. Use **Add Condition** for more rules.

## Analytics tab

Filters: period (e.g. **Last 30 days**) and **All Apps**.

- **KPI cards:** Total Sent, Delivered, Failed, Delivery Rate.
- **Summary counts:** Active campaigns, Campaigns this period, Segments, Active templates.
- **Charts:** Notifications Over Time; Campaigns by Type.
- **Recent Campaigns** table: Campaign, Type, Status, App, Sent, Delivered, Rate, Date.
- **What Notifications Produced:** taps, leads and orders attributed to opened notifications.

## History tab

Table columns: **Notification** (title and body), **Target** (app + audience type such as *Individual*), **Status**, **Delivery** (delivered / targeted), **Date**.

**Filters:** search, **Status** (All Status, Sent, Scheduled, Failed, Cancelled), **All Apps**, **Refresh**. A total count is shown, with pagination.

Click a row to expand it and see the **Full Title**, **Full Body**, **Image** URL and **Target Value**.

## Scheduled tab

Shows the number of queued notifications with a **Refresh** button. When empty, **Go to Compose** takes you back to schedule one.

## Best practices

- **Preview before sending** — check both Collapsed and Expanded views on Android and iPhone.
- **Prefer targeted audiences** — use topics, segments or specific users instead of All Users to avoid notification fatigue.
- **Use templates** for recurring messages and keep deep links pointing to production, not test sites.
- **Check Scheduled** before creating new sends to avoid duplicates.
- **Review Analytics and History** after each send to confirm delivery and catch failures.
